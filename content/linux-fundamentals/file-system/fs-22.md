## What are Hard Links?

A hard link is an additional name for an existing file. Both names point to the same data on disk.

## Understanding Inodes

**Inode:**
- Data structure storing file information
- Every file has an inode number
- Inode stores: permissions, owner, timestamps, data location
- Filename is just a link to an inode

## Creating Hard Links

```bash
# Syntax
ln <target> <link_name>

# Example
ln original.txt hardlink.txt
```

After creating a hard link:
- Both files have the same inode number
- Same file content
- Same permissions
- Deleting one doesn't affect the other

## Verifying Hard Links

```bash
# Check inode numbers
ls -li

# Output example:
# 12345 -rw-r--r-- 2 user group 100 original.txt
# 12345 -rw-r--r-- 2 user group 100 hardlink.txt
# Same inode (12345), link count is 2
```

## Characteristics

**Hard Link Properties:**
- Must be on same file system
- Cannot link directories (except by root, rarely)
- Increases link count
- All links are equal (no "original")

**Link Count:**
- Number in `ls -l` output (after permissions)
- Shows how many names point to this inode
- File deleted only when link count reaches 0

## Use Cases

**Backup without duplicating:**
```bash
# Creates reference, not copy
ln /var/data/file.txt /backup/file.txt
# Uses same disk space, not double
```

**File system snapshots:**
- Copy-on-write file systems use hard links
- Incremental backups

## Hard Links vs Symbolic Links

```bash
# Hard link
ln file.txt hardlink.txt

# Symbolic link
ln -s file.txt symlink.txt

# Delete original
rm file.txt

# Result:
# hardlink.txt - still works (same data)
# symlink.txt - broken (dangling link)
```

## Finding Hard Links

```bash
# Find all hard links to a file
find / -inum <inode_number> 2>/dev/null

# Example:
# If file has inode 12345
find / -inum 12345
```

## Limitation

Hard links don't work across different:
- Partitions
- File systems
- Devices

Use symbolic links for these cases.
