## /run - Runtime System Data

The `/run` directory contains runtime data for system processes since last boot.

## Characteristics

- **Temporary**: Cleared on reboot
- **Early boot**: Available early in boot process
- **Small**: Usually tmpfs (in RAM)
- **Variable**: Content changes as system runs

## What's Stored Here

**Process IDs (PIDs):**
- `/run/sshd.pid` - SSH daemon PID
- `/run/systemd/` - systemd runtime data

**Lock Files:**
- Prevent multiple instances of programs
- Coordinate resource access

**Socket Files:**
- Unix domain sockets
- Inter-process communication

**Device Information:**
- `/run/udev/` - udev device manager data
- `/run/blkid/` - Block device information

## Example Contents

```
/run/
├── lock/              # Lock files
├── user/              # User-specific runtime data
│   └── 1000/         # Runtime data for UID 1000
├── systemd/          # systemd runtime
├── sshd.pid          # SSH daemon PID
└── utmp              # Currently logged-in users
```

## Historical Context

Before `/run`, systems used:
- `/var/run/` - Now usually symlink to `/run`
- `/var/lock/` - Now usually symlink to `/run/lock`

Modern FHS standardized on `/run`.

## Practical Usage

```bash
# Check which user is logged in
who /run/utmp

# See SSH daemon PID
cat /run/sshd.pid

# View user runtime directory
ls /run/user/$UID/
```

## Why tmpfs?

Using tmpfs (RAM) for `/run`:
- Fast access
- Automatically cleared on boot
- Available early in boot process
