## The 6 R's of Cloud Migration

### 1. Rehost (Lift and Shift)

**Definition**: Move applications to cloud without modifications

**Benefits**: Quick migration, minimal risk
**Drawbacks**: Doesn't leverage cloud-native features

### 2. Replatform (Lift, Tinker, and Shift)

**Definition**: Make minimal cloud optimizations without changing core architecture

**Example**: Migrating database to managed cloud database service

### 3. Repurchase (Drop and Shop)

**Definition**: Move to a different product, typically SaaS

**Example**: Migrating from on-premises CRM to Salesforce

### 4. Refactor/Re-architect

**Definition**: Reimagine application architecture using cloud-native features

**Benefits**: Maximum cloud benefits, better scalability
**Drawbacks**: Time-consuming, expensive

### 5. Retire

**Definition**: Identify and decommission applications no longer needed

**Benefits**: Reduce complexity, lower costs

### 6. Retain

**Definition**: Keep certain applications on-premises

**Reasons**: Regulatory requirements, latency sensitivity, recent investments

## Migration Planning

**Assessment Phase**:
- Inventory applications and dependencies
- Identify migration candidates
- Assess cloud readiness

**Planning Phase**:
- Choose migration strategy for each application
- Design target architecture
- Create migration timeline

**Execution Phase**:
- Implement migrations in waves
- Test and validate
- Monitor and optimize
